# agent-doc-skills

三个 Agent Skills 让项目知识容易找到，无需每次会话都加载全部文档。每个 skill 使用简短的任务入口，详细流程保留在关联引用中。

## 安装

macOS、Linux 或 Windows，需已安装 Node.js：

```sh
npx skills add x0c/agent-doc-skills -g
```

安装工具提供 `doc-init`、`doc-compact`、`doc-update`，用于兼容 Agent Skills 的宿主。附带的辅助脚本需要 Python 3。安装后新开会话。

## 首次使用

```text
使用 doc-init，根据这个项目现有的权威资料建立文档体系。
```

已有项目按工作选择 skill：

| Skill | 用途 |
|---|---|
| [doc-init](doc-init/SKILL.md) | 安装或升级全局文档治理契约，建立缺失的项目文档，或刷新受影响范围的覆盖度。 |
| [doc-compact](doc-compact/SKILL.md) | 审计或压缩已授权范围的文档，保留已采纳需求并修复导航。 |
| [doc-update](doc-update/SKILL.md) | 保存可复用发现和产品决策，修正文档，并检查会话遗漏。 |

只读检查可说“使用 doc-compact 审计项目文档，不修改文件”。常规维护可说“使用 doc-update，将本次任务的可复用发现记录到对应文档”。

## 工作边界

已采纳的长期决策应先记录，再实现。用准确的内容摘要，让普通任务也能在设计决策前找到相关标准。压缩时保留范围、例外、证据、数值和脚本解析的标记。

当前文档治理预设为 v21。注入器探测真实全局指令文件，保留相邻用户内容和托管内容，不把全局预设注入产品指令文件。根目录 `AGENTS.md` 的修改使用独立的 `agents-md-edit` skill；缺失时报告能力缺口，不绕过它。

默认直接执行。外部 worker 必须得到明确授权，并遵守当前环境的模型政策；这些 skill 不授权原生子代理。只读审计不安装预设、不修复文件。局部维护不意味着全仓普查。权限、语言、Git/发布、记忆、平台和模型政策由用户及环境决定。

辅助脚本采集目录、代码信号、历史和可选数据库证据；领域归属与业务含义仍由 Agent 判断。链接与覆盖度报告只能证明实际检查过的范围。家目录相对 Markdown 链接按完整路径解析；报告成功不证明语义保留完整，也不保证未来模型遵守。

## 维护

唯一维护源为 `~/.config/agentsync/skills/`，本仓库由该源发布。可复用项目知识放在对应文档中，缺失证据应明确报告，不能编造。
